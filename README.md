# ГородАктив

**Платформа для поиска городских мероприятий с глубокой интеграцией в экосистему MAX**
```
[![License: Proprietary](https://img.shields.io/badge/License-Proprietary-red.svg)](LICENSE)
[![MAX Integration](https://img.shields.io/badge/MAX-WebApp-blueviolet)](https://max.ru)
```
---

## 1. Назначение решения

ГородАктив - это веб-приложение (Mini App) для поиска и записи на городские мероприятия: волонтерство, спорт, творчество, хакатоны и тематические встречи. Платформа решает проблему низкого вовлечения в городские активности, делая процесс записи бесшовным (в 2 клика) за счет интеграции с MAX.

Ключевые возможности:
- AI-помощник для подбора событий по текстовому запросу.
- Умная фильтрация по дате, цене, расстоянию и категории.
- Система геймификации: бейджи за достижения и учет волонтерских часов.
- Нативная интеграция с MAX: бесшовная авторизация, шеринг, UI-компоненты.

---

## 2. Основной пользовательский сценарий

1. Вход: Пользователь открывает приложение через MAX -> автоматическая бесшовная авторизация (без форм и паролей).
2. Поиск: Видит ленту событий или использует AI-помощник (например, "бесплатные события на выходных").
3. Выбор: Кликает на карточку -> переходит на экран деталей события.
4. Запись: Нажимает "Иду как участник" или "Хочу помочь организовать" (для волонтерских событий).
5. Награда: Получает Toast-уведомление об успехе. При достижении порога активности начисляется бейдж.
6. Шеринг: Делится событием с друзьями через нативную кнопку "Поделиться".
7. Профиль: Отслеживает прогресс: количество посещенных событий, полученные бейджи и накопленные волонтерские часы.

## 4. Команда для запуска всех локальных компонентов

Для воспроизводимого запуска всех сервисов одной командой используйте:

docker-compose up --build

Время сборки с нуля составляет менее 2 минут.
```
После запуска сервисы будут доступны по адресам:
- Frontend: http://localhost:5173
- Backend API: http://localhost:8000
- Swagger-документация: http://localhost:8000/docs
```

## 9. Внешние сервисы и интеграции

- MAX WebApp API: Бесшовная авторизация (initDataUnsafe), нативный шеринг (shareContent), управление окном (ready, expand).

- Яндекс.Карты (Deep Link): Открытие локации события в нативном приложении карт.

## 10. Описание работы с данными

Основные сущности:
- Event: событие (id, title, description, date, location, price, category, needsVolunteers).
- User: пользователь (id, name, avatar_url).
- Enrollment: запись на событие (user_id, event_id, role: "participant" | "volunteer").
- Badge / UserBadge: система достижений и выданных наград.
- VolunteerHours: накопленные часы волонтерской деятельности.

API-эндпоинты:
- GET /api/events - список всех событий.
- GET /api/events/{id} - детали конкретного события.
- POST /api/events/{id}/join - запись пользователя на событие.
- GET /api/profile?user_id={id} - статистика и данные профиля.
- GET /api/my-events?user_id={id} - список событий, на которые записан пользователь.

## 11. Порядок работы с тестовыми данными

1. При первом запуске через Docker бэкенд автоматически инициализирует базу данных тестовыми данными (сидами): 8 событий разных категорий, 3 пользователя, 5 видов бейджей.
2. Если автоматическая инициализация не сработала, выполните вручную:
   docker exec -it cityactive-backend python -m seed
3. Тестовый пользователь по умолчанию: user1 (эмулируется через maxBridge.getUserId() в dev-режиме).

## 12. Пошаговый сценарий проверки

1. Запуск: Выполните docker-compose up --build и откройте http://localhost:5173.
2. Главная: Убедитесь, что отображается лента из 6+ событий. Примените фильтр "Бесплатно" или введите запрос в AI-помощник.
3. Детали и запись: Кликните на карточку. Нажмите "Иду как участник". Должно появиться всплывающее уведомление (Toast) об успехе.
4. Волонтерство: Найдите событие с пометкой "Нужна помощь". Нажмите "Хочу помочь организовать". Убедитесь, что роль сохраняется как "Волонтер".
5. Профиль: Перейдите в профиль. Убедитесь, что счетчик "Событий" увеличился, а в списке "Мои события" отображается запись с корректной ролью.
6. Шеринг: Нажмите кнопку "Поделиться". Должно появиться уведомление "Ссылка скопирована!".

## 13. Примеры ожидаемого поведения системы

- Клик по карточке события: Плавный переход на экран деталей (анимация framer-motion).
- Повторная запись на то же событие: Toast с ошибкой: "Пользователь уже записан на это событие" (HTTP 409).
- Нажатие "Поделиться" на десктопе: Ссылка копируется в буфер обмена, появляется Toast-уведомление.
- Пустой список событий в профиле: Отображается Empty State с кнопкой "Найти событие", ведущей на главную.
- Заполненность события > 80%: Автоматическое появление бейджа "Популярно в твоем районе".

## 14. Известные ограничения

1. Дублирование ролей: Пользователь не может быть одновременно участником и волонтером на одном событии (возвращается HTTP 409 Conflict). Это осознанное архитектурное решение.
2. Clipboard API на HTTP: На мобильных устройствах без HTTPS современное Clipboard API блокируется браузером. Реализован fallback через execCommand('copy').
3. MAX WebApp функции: Методы shareContent, ready, expand работают корректно только внутри оболочки MAX. В обычном браузере применяются безопасные фоллбэки.
4. AI-помощник: В текущей MVP-версии работает как умный клиентский фильтр по ключевым словам и категориям, без обращения к внешним LLM-провайдерам.
5. Таймер обратного отсчета: На экране деталей работает локально (2 часа от момента открытия), не синхронизирован с сервером в рамках MVP.

## 15. Порядок остановки и повторного запуска решения
```
Остановка:
# Грациозная остановка всех контейнеров
docker-compose down

# Полная остановка с удалением томов (полный сброс базы данных)
docker-compose down -v

Повторный запуск:
# Обычный запуск в фоновом режиме
docker-compose up -d

# Пересборка образов (после внесения изменений в код)
docker-compose up --build -d

# Просмотр логов для отладки
docker-compose logs -f frontend
docker-compose logs -f backend

Перезапуск отдельного сервиса:
docker-compose restart backend
```
